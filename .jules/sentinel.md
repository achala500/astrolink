## 2026-11-04 - Private Signing Key Hardcoded in Source
**Vulnerability:** The Ed25519 private signing key `_MASTER_PRIVATE_KEY_HEX` was hardcoded directly in `backend/app/licensing.py`. In binary distributions (built via PyInstaller or Docker), reverse engineering or decompilation would expose this key, enabling anyone to forge unlimited lifetime licenses and bypass the offline cryptographic licensing system.
**Learning:** Utilities for minting/generating signed payloads were collocated with the client validation code in `backend/app/licensing.py`. As a result, a default private key was bundled alongside the public verification logic for convenience.
**Prevention:** Asymmetric crypto architectures must strictly isolate the private signing key to secure server/build environments. Client/binary code must only ever bundle the public key. Any minting utilities must require private keys to be injected explicitly via secure environment variables (`ASTROLINK_MASTER_PRIVATE_KEY` / `ASTROLINK_PRIVATE_KEY`) or caller arguments, failing fast with an exception if absent.
